Add Two Numbers, digit by digit

Two numbers arrive as linked lists, one digit per node, stored backwards. You add them the same way you learned on paper: one column at a time, starting from the ones place, carrying a 1 when a column goes past 9.

Understand the problem

What are we being asked?

You get two non-negative whole numbers, but not as normal numbers. Each one is a linked list of single digits, written backwards. Your job is to add the two numbers and hand back the total in the same backwards linked-list form.

Input and output

You get

l1 and l2: the first node of each list. Each list has at least one node, and each node holds one digit, 0 to 9.

You return

The first node of a new linked list holding the sum, also one digit per node and also backwards.

What's a linked list? Think of a treasure hunt

You're handed one clue card. It shows a digit and says where the next card is hidden. That card has another digit and directions to the one after it. The last card says "the end". You can't skip ahead or count cards in advance: the only way to read them is to follow the directions one by one, starting from the first card.

A linked list works exactly like that. Each clue card is a node. The digit is its val, the directions are its next pointer, "the end" is null, and the first card you're handed is the head.

// what a node looks like in code
class ListNode {

    this.next = next;  // next node, or null
  }

We usually draw a list neatly in a row like this. Walking from the head, the first digit you meet is the ones digit, then tens, then hundreds. That's why the problem calls it "reverse order": written as a normal number, you read it right to left.

Array

Items sit side by side with numbered positions. You can jump straight to nums[2].

Linked list

No positions to jump to. You hold the head and follow next one node at a time until you hit null.

Why it helps here

Walking from the head gives you ones, then tens, then hundreds. That's the same order you add digits on paper.

The examples, explained

Example 1
[2,4,3] + [5,6,4] → [7,0,8]342 + 465 = 807. The 6 + 4 column makes 10, so a 1 carries into the hundreds.
Example 2
[0] + [0] → [0]0 + 0 = 0. The smallest possible input still returns one node, not an empty list.
Example 3
[9,9,9,9,9,9,9] + [9,9,9,9] → [8,9,9,9,0,0,0,1]9,999,999 + 9,999 = 10,009,998. The lists have different lengths, and the answer is one node longer than both.

The rules, in plain words

ConstraintWhat it means for you
1 to 100 nodes per listNeither list is ever empty. But a number can be 100 digits long, far too big to store in a normal integer variable.
0 ≤ Node.val ≤ 9Every node is one digit. The biggest column is 9 + 9 + a carry of 1 = 19, so the carry is only ever 0 or 1.
No leading zerosThe last node isn't 0, unless the whole number is just 0. Adding digit by digit never creates leading zeros either.

Check yourself

What number does [1 → 0 → 9] represent?

901. The head, 1, is the ones digit. Read right to left: 9, 0, 1.

l1 = [9] and l2 = [1]. What should you return?

[0 → 1]. 9 + 1 = 10, and 10 stored backwards is 0 then 1. The answer can be longer than both inputs.

l1 = [5, 1] and l2 = [3]. What happens after the first column?

l2 has run out, so treat its missing digit as 0. 15 + 3 = 18, returned as [8 → 1].

The plan, before any code

This is just the addition you already know from school. The lists happen to give you the digits in exactly the order you need.

  1. Start at the head of both lists. These are the ones digits.
  2. Add the two digits and the carry. If one list has run out, use 0 for its digit.
  3. Keep the last digit of that sum as a new node in the answer. Carry the rest, which is 0 or 1, to the next column.
  4. Move both lists forward one node and repeat, as long as either list has nodes left or the carry isn't 0.
  5. Return the head of the new list.

Three things that trip up beginners

Each one is handled by a single small detail in the code. Try the matching example to watch it happen.

The lists can have different lengths

When one list runs out, treat its missing digit as 0. That's what l1 ? l1.val : 0 does. You'll see a dashed ghost node with a 0 in it.

A carry can be left over at the end

5 + 5 = 10 has two digits even though both inputs have one. The loop keeps going while carry is not 0, which adds that final 1 node.

The first node needs somewhere to attach

A placeholder dummy node sits in front of the result, so every new digit is attached the same way: tail.next = new node. At the end, return dummy.next to skip it.

Why not just turn the lists into numbers?

It's tempting: read 342 and 465, add them, then split 807 back into nodes. But each list can have up to 100 nodes, which means 100-digit numbers. A normal 64-bit integer holds about 19 digits, and JavaScript numbers lose precision after about 15 or 16. Adding digit by digit works for any length, and it's what the problem is really testing.

O(max(m, n))time: each node is visited once
O(max(m, n))space for the answer list, plus O(1) extra (just carry and a few pointers)
