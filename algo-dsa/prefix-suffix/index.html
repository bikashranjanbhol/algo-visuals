When solving array problems, we often need information about:

  • everything before a position,
  • everything after a position,
  • the sum of a range,
  • the maximum element seen so far,
  • the minimum element remaining on the right,
  • the XOR of a subarray,
  • how many times something has appeared up to a point,
  • or some combination of left-side and right-side information.

A very common mistake is to recalculate this information again and again.

For example, suppose we have:

Array = [2, 4, 1, 7, 3]

If we repeatedly ask:

What is the sum from index 0 to index 3?
What is the sum from index 0 to index 2?
What is the maximum from index 0 to index 4?
What is the maximum from index 0 to index 2?

we could scan the array every time.

But that becomes inefficient.

Instead, we can precompute information while moving from left to right or right to left.

That is the main idea behind prefix and suffix techniques.

1. What Does "Prefix" Mean?

A prefix of an array is a portion starting from the beginning.

Consider:

A = [5, 2, 8, 3]

Its prefixes are:

[5]
[5, 2]
[5, 2, 8]
[5, 2, 8, 3]

So when we say:

prefix information at index i

we usually mean information about:

A[0 ... i]

For example:

Prefix Sum[i]
Prefix Maximum[i]
Prefix Minimum[i]
Prefix XOR[i]

all describe some property of the elements from index 0 through index i.

2. What Does "Suffix" Mean?

A suffix is the opposite.

A suffix ends at the end of the array.

For:

A = [5, 2, 8, 3]

the suffixes are:

[5, 2, 8, 3]
   [2, 8, 3]
      [8, 3]
         [3]

So:

suffix information at index i

usually describes:

A[i ... n-1]

Examples include:

Suffix Sum[i]
Suffix Maximum[i]
Suffix Minimum[i]
Suffix XOR[i]

3. Prefix Sum

Prefix Sum is probably the most common prefix technique.

Suppose:

A = [2, 4, 1, 7, 3]

We define:

prefixSum[i] = sum of A[0] through A[i]

Therefore:

Index:        0   1   2   3   4
Array:        2   4   1   7   3
Prefix Sum:   2   6   7  14  17

Explanation:

prefixSum[0] = 2

prefixSum[1] = 2 + 4
             = 6

prefixSum[2] = 2 + 4 + 1
             = 7

prefixSum[3] = 2 + 4 + 1 + 7
             = 14

prefixSum[4] = 2 + 4 + 1 + 7 + 3
             = 17

But we do not need to recalculate everything.

Notice:

prefixSum[i] = prefixSum[i - 1] + A[i]

So the implementation is:

vector<int> prefix(n);

prefix[0] = a[0];

for (int i = 1; i < n; i++) {
    prefix[i] = prefix[i - 1] + a[i];
}

Time complexity:

O(n)

4. The Most Useful Prefix Sum Version

There is another version that is often even easier to use.

Instead of creating a prefix array of size n, create one of size:

n + 1

Define:

prefix[0] = 0

and:

prefix[i + 1] = prefix[i] + A[i]

Example:

A = [2, 4, 1, 7, 3]

Then:

prefix = [0, 2, 6, 7, 14, 17]

Code:

vector<long long> prefix(n + 1, 0);

for (int i = 0; i < n; i++) {
    prefix[i + 1] = prefix[i] + a[i];
}

This version makes range sum calculations especially clean.

5. Range Sum Using Prefix Sum

Suppose we want the sum of:

A[L ... R]

With normal iteration, this takes:

O(R - L + 1)

But with prefix sums, it becomes:

O(1)

Using the n + 1 version:

sum(L, R) = prefix[R + 1] - prefix[L]

For example:

A = [2, 4, 1, 7, 3]

Find sum from index 1 to index 3.

The elements are:

4 + 1 + 7 = 12

Prefix array:

[0, 2, 6, 7, 14, 17]

Therefore:

prefix[4] - prefix[1]

= 14 - 2
= 12

Code:

long long rangeSum(int l, int r) {
    return prefix[r + 1] - prefix[l];
}

This is one of the most important formulas in array problems.

6. Why Prefix Sum Is Powerful

Imagine:

n = 100000
q = 100000

You receive 100000 range-sum queries.

If you calculate each range manually, the worst case can be approximately:

O(n × q)

which could mean around:

10^10 operations

That is too slow.

Using Prefix Sum:

Build prefix array: O(n)
Each query:          O(1)

Total: O(n + q)

This is a huge improvement.

Try it: pick L and R and watch which two prefix cells are used, then see the n × q difference with your own numbers.

Use an array of size n+1 with prefix[0] = 0. Then the sum of any range A[L … R] is prefix[R+1] − prefix[L]: the unwanted left part is subtracted away. Pick L and R and watch which two cells are used.

Why it matters at scale

n elements, q range queries. Rescanning costs about n per query; prefix sums cost n once, then 1 per query.

7. Suffix Sum

Suffix Sum is the same idea, but we calculate from right to left.

Define:

suffixSum[i] = sum of A[i ... n-1]

Consider:

A = [2, 4, 1, 7, 3]

Then:

Index:        0   1   2   3   4
Array:        2   4   1   7   3
Suffix Sum:  17  15  11  10   3

Formula:

suffix[i] = A[i] + suffix[i + 1]

Code:

vector<long long> suffix(n);

suffix[n - 1] = a[n - 1];

for (int i = n - 2; i >= 0; i--) {
    suffix[i] = a[i] + suffix[i + 1];
}

8. Prefix Maximum

Prefix techniques are not limited to sums.

We can store the maximum value seen so far.

Define:

prefixMax[i] = maximum value in A[0 ... i]

Example:

A = [3, 1, 5, 2, 8, 4]

Then:

Index:        0   1   2   3   4   5
Array:        3   1   5   2   8   4
Prefix Max:   3   3   5   5   8   8

Formula:

prefixMax[i] = max(prefixMax[i - 1], A[i])

Code:

vector<int> prefixMax(n);

prefixMax[0] = a[0];

for (int i = 1; i < n; i++) {
    prefixMax[i] = max(prefixMax[i - 1], a[i]);
}

Think of it as asking:

What is the largest number I have seen so far?

9. Suffix Maximum

Similarly:

suffixMax[i] = maximum value in A[i ... n-1]

For:

A = [3, 1, 5, 2, 8, 4]

we get:

Index:        0   1   2   3   4   5
Array:        3   1   5   2   8   4
Suffix Max:   8   8   8   8   8   4

Formula:

suffixMax[i] = max(A[i], suffixMax[i + 1])

Code:

vector<int> suffixMax(n);

suffixMax[n - 1] = a[n - 1];

for (int i = n - 2; i >= 0; i--) {
    suffixMax[i] = max(a[i], suffixMax[i + 1]);
}

10. Prefix Minimum

We can do exactly the same thing with minimum values.

Define:

prefixMin[i] = minimum of A[0 ... i]

Example:

A = [8, 5, 9, 3, 6, 1]

Then:

Array:        8   5   9   3   6   1
Prefix Min:   8   5   5   3   3   1

Formula:

prefixMin[i] = min(prefixMin[i - 1], A[i])

Code:

vector<int> prefixMin(n);

prefixMin[0] = a[0];

for (int i = 1; i < n; i++) {
    prefixMin[i] = min(prefixMin[i - 1], a[i]);
}

11. Suffix Minimum

Define:

suffixMin[i] = minimum of A[i ... n-1]

Example:

A = [4, 7, 2, 9, 5]

Then:

Array:        4   7   2   9   5
Suffix Min:   2   2   2   5   5

Code:

vector<int> suffixMin(n);

suffixMin[n - 1] = a[n - 1];

for (int i = n - 2; i >= 0; i--) {
    suffixMin[i] = min(a[i], suffixMin[i + 1]);
}

12. The General Prefix Formula

Many prefix arrays follow this structure:

prefix[i] = combine(prefix[i - 1], A[i])

where combine could be:

+
max
min
XOR
GCD
AND
OR
count

So prefix techniques are really about:

Accumulating information from left to right.

Suffix techniques are:

Accumulating information from right to left.

Try it: pick any combine operation and direction and watch the recurrence fill the array one cell at a time.

Every prefix array comes from one recurrence: prefix[i] = combine(prefix[i−1], A[i]). Pick the operation and the direction, then watch it fill in. The code updates to match.

Time: one pass, O(n). Each cell costs one combine, which is why rescanning is never needed.

13. Prefix XOR

XOR is another popular prefix operation.

Define:

prefixXor[i] = A[0] ^ A[1] ^ ... ^ A[i]

Using the n + 1 style:

vector<int> prefixXor(n + 1, 0);

for (int i = 0; i < n; i++) {
    prefixXor[i + 1] = prefixXor[i] ^ a[i];
}

Now we can calculate XOR of:

A[L ... R]

using:

prefixXor[R + 1] ^ prefixXor[L]

Why does this work?

Because:

x ^ x = 0

and:

x ^ 0 = x

14. Prefix Frequency / Prefix Count

Sometimes we want to know how many times something has appeared up to an index.

For example:

A = [1, 0, 1, 1, 0, 1]

Suppose we want to know:

How many 1s are there from index L to R?

Create:

vector<int> prefixOnes(n + 1, 0);

for (int i = 0; i < n; i++) {
    prefixOnes[i + 1] = prefixOnes[i] + (a[i] == 1);
}

Then:

number of ones in [L, R]
=
prefixOnes[R + 1] - prefixOnes[L]

The expression:

(a[i] == 1)

is:

1 if true
0 if false

So we are effectively prefix-summing a condition.

15. Prefix Count for Characters

The same idea works with strings.

Suppose:

s = "abacaba"

We may want queries such as:

How many 'a' characters exist between L and R?

Create:

vector<int> prefixA(n + 1, 0);

for (int i = 0; i < n; i++) {
    prefixA[i + 1] = prefixA[i] + (s[i] == 'a');
}

Query:

int countA = prefixA[r + 1] - prefixA[l];

For all lowercase characters:

vector<array<int, 26>> prefix(n + 1);

for (int i = 0; i < n; i++) {
    prefix[i + 1] = prefix[i];
    prefix[i + 1][s[i] - 'a']++;
}

Then character frequency in [L, R] is:

prefix[r + 1][c - 'a'] - prefix[l][c - 'a'];

16. Prefix GCD

We can store the GCD of everything seen so far.

Define:

prefixGcd[i] = gcd(A[0], A[1], ..., A[i])

Code:

vector<int> prefixGcd(n);

prefixGcd[0] = a[0];

for (int i = 1; i < n; i++) {
    prefixGcd[i] = gcd(prefixGcd[i - 1], a[i]);
}

Similarly:

vector<int> suffixGcd(n);

suffixGcd[n - 1] = a[n - 1];

for (int i = n - 2; i >= 0; i--) {
    suffixGcd[i] = gcd(a[i], suffixGcd[i + 1]);
}

Suppose we want the GCD of the entire array after removing index i.

Everything before i is represented by:

prefixGcd[i - 1]

Everything after i is represented by:

suffixGcd[i + 1]

Therefore:

answer = gcd(prefixGcd[i - 1], suffixGcd[i + 1])

17. Prefix Product

We can also store products.

prefixProduct[i]
=
A[0] × A[1] × ... × A[i]

Formula:

prefixProduct[i]
=
prefixProduct[i - 1] × A[i]

Code:

vector<long long> prefixProduct(n);

prefixProduct[0] = a[0];

for (int i = 1; i < n; i++) {
    prefixProduct[i] = prefixProduct[i - 1] * a[i];
}

Be careful because products can become very large and cause integer overflow.

Sometimes problems use:

product modulo M

In that case:

prefixProduct[i] =
    (prefixProduct[i - 1] * a[i]) % MOD;

Unlike sums, range-product queries are not always safely computed by division because:

  • values may contain zero,
  • modular division is different,
  • modular inverse may not exist.

18. Product of Array Except Self

A famous prefix/suffix problem is:

For every index, return the product of all elements except the current one.

Example:

A = [1, 2, 3, 4]

Answer:

[24, 12, 8, 6]

We can calculate:

prefix product to the left
×
suffix product to the right

Create:

vector<long long> left(n, 1);
vector<long long> right(n, 1);

Build left product:

for (int i = 1; i < n; i++) {
    left[i] = left[i - 1] * a[i - 1];
}

Now build right product:

for (int i = n - 2; i >= 0; i--) {
    right[i] = right[i + 1] * a[i + 1];
}

Finally:

answer[i] = left[i] * right[i];

Try it: the three passes animated.

The most important prefix + suffix pattern: for each index, combine what's strictly to its left with what's strictly to its right. Product of Array Except Self is the classic. Watch the two passes build left and right, then multiply.

left[i] = product of A[0 … i−1] // strictly before i right[i] = product of A[i+1 … n−1] // strictly after i ans[i] = left[i] * right[i] // in code, left is built left-to-right, right is built right-to-left left[0] = 1; for (i = 1 … n−1) left[i] = left[i−1] * A[i−1]; right[n−1] = 1; for (i = n−2 … 0) right[i] = right[i+1] * A[i+1];

Including vs excluding the current element

A prefix that includes i is prefix[i]. "Strictly before i" is prefix[i−1], and "strictly after i" is suffix[i+1]. Most bugs in this pattern come from mixing those up, and from forgetting that i = 0 has nothing to its left and i = n−1 has nothing to its right. Use an identity value (0 for sum, 1 for product, −∞ for max) at the edges.

19. The "Everything Except Me" Pattern

One of the most important prefix/suffix patterns is:

information before index i
+
information after index i

Conceptually:

LEFT SIDE | current element | RIGHT SIDE

For every position, we may want to know something about:

A[0 ... i-1]

and:

A[i+1 ... n-1]

Prefix and suffix arrays make both sides available instantly.

For example:

prefixMax[i - 1]
suffixMax[i + 1]

give the maximum values strictly before and after i.

20. Including the Current Element vs Excluding It

This distinction is extremely important.

Suppose:

prefixMax[i]

is defined as:

maximum of A[0 ... i]

Then it includes A[i].

But sometimes we need:

maximum strictly before i

That is:

prefixMax[i - 1]

Similarly:

suffixMax[i]

includes A[i].

The maximum strictly after i is:

suffixMax[i + 1]

Many bugs happen because programmers accidentally include the current element when they need to exclude it.

21. Prefix Maximum + Suffix Maximum Example

Suppose:

A = [2, 7, 3, 5, 4]

Prefix maximum:

[2, 7, 7, 7, 7]

Suffix maximum:

[7, 7, 5, 5, 4]

Suppose we want:

For every index, what is the largest value anywhere except at this index?

For index i, use:

max(
    prefixMax[i - 1],
    suffixMax[i + 1]
)

with special handling for the first and last positions.

22. Prefix Min + Suffix Max Pattern

Sometimes the left and right sides store different kinds of information.

For example, consider the classic stock-profit problem:

Buy a stock on one day and sell it later. Find maximum profit.

Suppose:

prices = [7, 1, 5, 3, 6, 4]

A prefix minimum array is:

[7, 1, 1, 1, 1, 1]

A suffix maximum array is:

[7, 6, 6, 6, 6, 4]

For every possible boundary:

profit = future maximum - past minimum

The broader lesson is:

Prefix and suffix arrays do not need to contain the same type of information.

Try it: move the sell day and see prefix min pick the buy day.

Stock profit: prefix min meets suffix max

Buy low on an earlier day, sell high on a later day. Prefix min answers "cheapest so far", suffix max answers "best price still coming". The two sides store different things, which is allowed.

sell on day 1

23. Prefix Boolean Information

Prefix values do not need to be numbers.

Suppose we want to know:

Are all values up to index i positive?

Code:

vector<bool> prefixValid(n);

prefixValid[0] = (a[0] > 0);

for (int i = 1; i < n; i++) {
    prefixValid[i] =
        prefixValid[i - 1] && (a[i] > 0);
}

Similarly we can build a suffix Boolean state.

24. Prefix OR and Prefix AND

Prefix OR:

prefixOr[0] = a[0];

for (int i = 1; i < n; i++) {
    prefixOr[i] = prefixOr[i - 1] | a[i];
}

Prefix AND:

prefixAnd[0] = a[0];

for (int i = 1; i < n; i++) {
    prefixAnd[i] = prefixAnd[i - 1] & a[i];
}

Suffix versions work exactly the same way, but iterate backward.

25. Running Count Is Also a Prefix Concept

Suppose:

A = [4, -1, 8, -3, -6, 9]

We want:

number of negative elements up to every index

Then:

Array:            4  -1   8  -3  -6   9
Negative Count:   0   1   1   2   3   3

Code:

vector<int> countNegative(n);

countNegative[0] = (a[0] < 0);

for (int i = 1; i < n; i++) {
    countNegative[i] =
        countNegative[i - 1] + (a[i] < 0);
}

26. Prefix Balance

Prefix techniques are often hidden inside problems involving balances.

Consider:

"(()())"

Assign:

'(' = +1
')' = -1

Then calculate prefix sum.

Character:      (   (   )   (   )   )
Value:          1   1  -1   1  -1  -1
Prefix Balance: 1   2   1   2   1   0

For a valid parentheses sequence:

  1. Prefix balance must never become negative.
  2. Final balance must be zero.

27. Difference Arrays and Prefix Sums

Suppose:

A = [5, 8, 10, 7]

The difference array is:

[5, 3, 2, -3]

because:

diff[0] = 5
diff[1] = 8 - 5 = 3
diff[2] = 10 - 8 = 2
diff[3] = 7 - 10 = -3

If we take prefix sums of the difference array, we reconstruct the original array.

So:

A difference array and a prefix sum are inverse-like concepts.

28. Difference Array for Range Updates

Suppose we repeatedly need to perform:

Add x to every element in A[L ... R]

Instead of updating every element, use:

diff[L] += x;

if (R + 1 < n) {
    diff[R + 1] -= x;
}

After all updates, calculate the prefix sum of diff.

Example:

A = [0, 0, 0, 0, 0]

Add 3 to indices 1 through 3.

Then:

diff = [0, 3, 0, 0, -3]

Its prefix sum is:

[0, 3, 3, 3, 0]

Try it: add range updates and watch one prefix sum rebuild the array.

Difference array: range updates in O(1)

The inverse trick. To add x to every element in A[L … R], write +x at L and −x at R+1 in a difference array. One prefix sum at the end rebuilds the real values, no matter how many updates you made.

29. Prefix Sum in Two Dimensions

Prefix sums are not limited to one-dimensional arrays.

Suppose we have:

1 2 3
4 5 6
7 8 9

A 2D prefix sum stores the sum of the rectangle from (0, 0) to (i, j).

A common formula is:

prefix[i + 1][j + 1]
=
matrix[i][j]
+ prefix[i][j + 1]
+ prefix[i + 1][j]
- prefix[i][j]

Code:

vector<vector<long long>> prefix(
    rows + 1,
    vector<long long>(cols + 1, 0)
);

for (int i = 0; i < rows; i++) {
    for (int j = 0; j < cols; j++) {
        prefix[i + 1][j + 1] =
            matrix[i][j]
            + prefix[i][j + 1]
            + prefix[i + 1][j]
            - prefix[i][j];
    }
}

30. Prefix Max Cannot Be Used Like Prefix Sum for Arbitrary Range Maximum

With sums:

sum(L, R)
=
prefixSum[R + 1] - prefixSum[L]

because subtraction removes the unwanted prefix.

But maximum has no simple inverse.

There is no equivalent:

prefixMax[R] - prefixMax[L - 1]

For general range maximum queries, common tools include:

  • Segment Tree
  • Sparse Table
  • Deque for sliding-window maximum
  • Other problem-specific structures

Prefix Max is still extremely useful when the range always starts at index 0.

31. Which Operations Support Easy Range Queries?

Sum

Yes.

rangeSum = prefix[R + 1] - prefix[L]

XOR

Yes.

rangeXor = prefixXor[R + 1] ^ prefixXor[L]

Count

Yes, because count is basically sum.

rangeCount = prefixCount[R + 1] - prefixCount[L]

Product

Sometimes, but division, zeros, and modulo can make it difficult.

Maximum

Not directly.

Minimum

Not directly.

GCD

Not directly through simple subtraction.

32. Common Prefix/Suffix Template

Generic prefix template:

vector<int> prefix(n);

prefix[0] = a[0];

for (int i = 1; i < n; i++) {
    prefix[i] = combine(prefix[i - 1], a[i]);
}

Generic suffix template:

vector<int> suffix(n);

suffix[n - 1] = a[n - 1];

for (int i = n - 2; i >= 0; i--) {
    suffix[i] = combine(a[i], suffix[i + 1]);
}

33. A Helpful Mental Model

Imagine standing at index i.

0 1 2 3 4 5 6
      ↑
      i

Everything on your left:

0 ... i-1

can often be summarized by a prefix array.

Everything on your right:

i+1 ... n-1

can often be summarized by a suffix array.

So instead of repeatedly scanning:

← ← ← i → → →

you precompute both directions once.

34. Example: Find an Index Where Left Sum Equals Right Sum

Suppose:

A = [1, 7, 3, 6, 5, 6]

We want an index where:

sum before i = sum after i

At index 3:

Left:
1 + 7 + 3 = 11

Right:
5 + 6 = 11

Code:

long long total = 0;

for (int x : a) {
    total += x;
}

long long left = 0;

for (int i = 0; i < n; i++) {
    long long right = total - left - a[i];

    if (left == right) {
        return i;
    }

    left += a[i];
}

Sometimes we only need a running prefix value, not the whole array.

Try it: slide i until the left and right sums match.

Pivot index: left sum equals right sum

Move i. Left is the sum strictly before i, right is the sum strictly after. You don't even need an array here: a running total is enough, because right = total − left − A[i].

i = 0

35. When Do We Actually Need the Full Prefix Array?

Use a full prefix array when you need to access prefix information for many different indices later.

For example, many range queries need stored prefix sums.

But if you process the array only once from left to right, you may only need:

long long runningSum = 0;

instead of:

vector<long long> prefix(n);

36. Prefix/Suffix Without Extra Arrays

Consider Product of Array Except Self.

vector<int> productExceptSelf(vector<int>& nums) {
    int n = nums.size();

    vector<int> ans(n, 1);

    int prefix = 1;

    for (int i = 0; i < n; i++) {
        ans[i] = prefix;
        prefix *= nums[i];
    }

    int suffix = 1;

    for (int i = n - 1; i >= 0; i--) {
        ans[i] *= suffix;
        suffix *= nums[i];
    }

    return ans;
}

This gives:

O(n) time
O(1) extra space

excluding the output array.

37. Prefix Best + Current + Suffix Best

Some problems ask us to choose something from:

left side
current position
right side

For example:

best value before i
+
A[i]
+
best value after i

This might become:

answer = max(
    answer,
    prefixBest[i - 1]
    + a[i]
    + suffixBest[i + 1]
);

The meaning of "best" depends on the problem.

38. Prefix Best Is Not Always Prefix Maximum

Suppose we are solving a maximum-subarray-related problem.

The prefix information may store:

best subarray ending before i

rather than just:

largest single value before i

Similarly, suffix information may store:

best subarray starting after i

So "prefix" and "suffix" describe direction, not the specific operation.

39. Prefix and Kadane's Algorithm

Kadane's Algorithm can also be viewed as a directional dynamic-programming idea.

For each index:

bestEnding[i]
=
maximum subarray sum ending exactly at i

Formula:

bestEnding[i]
=
max(
    A[i],
    bestEnding[i - 1] + A[i]
)

This is calculated from left to right.

Similarly we could calculate bestStarting[i] from right to left.

40. Prefix/Suffix in String Problems

Prefix and suffix concepts are extremely common with strings.

Examples include:

  • character counts,
  • validity of prefixes,
  • prefix hashes,
  • KMP prefix function,
  • Z-function.

The underlying idea is still efficient reuse of information about prefixes or suffixes.

41. Prefix Hashing

A prefix hash stores the hash of:

s[0 ... i]

With the right mathematical adjustment, it lets us derive the hash of:

s[L ... R]

efficiently.

This is useful for:

  • substring comparison,
  • palindrome algorithms,
  • duplicate substring detection,
  • pattern matching.

42. Prefix and Suffix in Trapping Rain Water

For every index i, the amount of trapped water depends on:

maximum wall on the left

and:

maximum wall on the right

The formula is:

water[i]
=
min(leftMax[i], rightMax[i]) - height[i]

if the result is positive.

43. Prefix/Suffix in Partition Problems

Suppose we split an array between i and i + 1.

LEFT | RIGHT

Then we may want:

sum(left)
sum(right)

or:

max(left)
min(right)

or:

GCD(left)
GCD(right)

Prefix and suffix arrays are perfect for this.

44. Example: Find a Valid Split Using Prefix Max and Suffix Min

Suppose we want to split an array so that:

every value on the left
<=
every value on the right

That condition becomes:

maximum(left)
<=
minimum(right)

So calculate:

prefixMax[i]

and:

suffixMin[i]

Then test:

if (prefixMax[i] <= suffixMin[i + 1]) {
    // valid split after index i
}

45. Common Mistake: Wrong Suffix Loop Direction

Prefix usually goes:

for (int i = 1; i < n; i++)

Suffix usually goes backward:

for (int i = n - 2; i >= 0; i--)

This is because suffix[i] often depends on suffix[i + 1].

46. Common Mistake: Out-of-Bounds Access

Suppose you write:

prefixMax[i - 1]

when:

i = 0

That is invalid.

Similarly:

suffixMax[i + 1]

is invalid when:

i = n - 1

Handle boundaries carefully:

int left = (i > 0)
    ? prefixMax[i - 1]
    : INT_MIN;

int right = (i + 1 < n)
    ? suffixMax[i + 1]
    : INT_MIN;

47. Common Mistake: Integer Overflow

Suppose:

A[i] <= 10^9
n <= 10^5

Then the total sum may be roughly:

10^14

which does not fit in a 32-bit int.

Use:

long long

for prefix sums.

48. Common Mistake: Confusing Indexing Conventions

Two popular definitions exist.

Style 1

prefix[i] = sum A[0 ... i]

Range sum:

prefix[R] - prefix[L - 1]

with special handling for L = 0.

Style 2

prefix[0] = 0
prefix[i + 1] = prefix[i] + A[i]

Range sum:

prefix[R + 1] - prefix[L]

The second style usually produces cleaner code and fewer edge cases.

49. Recommended Prefix Sum Template

int n;
cin >> n;

vector<long long> a(n);

for (auto &x : a) {
    cin >> x;
}

vector<long long> prefix(n + 1, 0);

for (int i = 0; i < n; i++) {
    prefix[i + 1] = prefix[i] + a[i];
}

Range sum:

long long sum = prefix[r + 1] - prefix[l];

50. Recommended Prefix Maximum Template

vector<int> prefixMax(n);

prefixMax[0] = a[0];

for (int i = 1; i < n; i++) {
    prefixMax[i] =
        max(prefixMax[i - 1], a[i]);
}

51. Recommended Suffix Maximum Template

vector<int> suffixMax(n);

suffixMax[n - 1] = a[n - 1];

for (int i = n - 2; i >= 0; i--) {
    suffixMax[i] =
        max(a[i], suffixMax[i + 1]);
}

52. Recommended Prefix/Suffix Min Template

Prefix:

vector<int> prefixMin(n);

prefixMin[0] = a[0];

for (int i = 1; i < n; i++) {
    prefixMin[i] =
        min(prefixMin[i - 1], a[i]);
}

Suffix:

vector<int> suffixMin(n);

suffixMin[n - 1] = a[n - 1];

for (int i = n - 2; i >= 0; i--) {
    suffixMin[i] =
        min(a[i], suffixMin[i + 1]);
}

54. How to Recognize Prefix/Suffix Problems

Look for phrases such as:

maximum before i
minimum after i
elements to the left
elements to the right
all elements except current
split the array
remove one element
many range queries
number of occurrences between L and R
best value seen so far
maximum remaining on the right

These are strong signs that prefix or suffix preprocessing may help.

55. A Step-by-Step Strategy

When facing a new problem, ask:

  1. Am I repeatedly scanning the same left or right portion?
  2. What information do I actually need?
  3. Is the information about the left side?
  4. Is it about the right side?
  5. Does the problem ask about both sides of every index?
  6. Can I replace an entire array with a running variable?

Possible information includes:

sum
maximum
minimum
count
XOR
GCD
product
Boolean state

56. Prefix/Suffix vs Brute Force

Brute force example:

for (int i = 0; i < n; i++) {
    int mx = INT_MIN;

    for (int j = 0; j <= i; j++) {
        mx = max(mx, a[j]);
    }
}

Complexity:

O(n²)

Using a prefix maximum:

O(n)

The core optimization is:

Do not repeatedly recompute information that can be carried forward.

57. Prefix/Suffix Is a Form of Precomputation

Prefix and suffix techniques belong to a larger idea called precomputation.

Instead of repeatedly doing expensive work during queries or iterations, we calculate useful information once.

We spend:

O(n)

upfront so later operations become:

O(1)

or much cheaper.

The same mindset appears in:

  • dynamic programming,
  • sparse tables,
  • factorial precomputation,
  • sieve algorithms,
  • hashing,
  • lookup tables.

58. Prefix/Suffix as Dynamic Programming

Consider:

prefixMax[i]
=
max(prefixMax[i - 1], A[i])

This is a recurrence relation.

The answer at position i depends on the answer at i - 1.

Similarly:

suffixMin[i]
=
min(A[i], suffixMin[i + 1])

builds answers backward.

So prefix/suffix techniques can also be viewed as:

One-dimensional dynamic programming where state flows in one direction.

Check yourself

A = [2, 4, 1, 7, 3]. What's the sum of A[1 … 3] using the n+1 prefix array?

prefix = [0, 2, 6, 7, 14, 17]. Sum = prefix[4] − prefix[1] = 14 − 2 = 12, which is 4 + 1 + 7.

Why can't you get the max of A[2 … 4] from a prefix max array?

prefixMax[4] tells you the biggest value in A[0 … 4], but you can't "subtract" A[0 … 1] out of it: if the overall max sits at index 0, you have no idea what the max of A[2 … 4] is. Max has no inverse.

For "product except self", what should left[0] and right[n−1] be?

1, the identity for multiplication: there's nothing to the left of index 0 and nothing to the right of the last index, and multiplying by 1 changes nothing.

You add 5 to A[2 … 4] and 2 to A[0 … 1] using a difference array of length 6. What does diff look like?

diff = [2, 0, 3, 0, 0, −5]. Start +2 at 0, cancel with −2 at 2, start +5 at 2 (so index 2 nets +3), cancel with −5 at 5. Prefix-summing gives [2, 2, 5, 5, 5, 0].

61. The Most Important Idea to Remember

Do not memorize prefix sum as only a formula.

Understand the broader pattern:

PREFIX
=
information accumulated from left to right

SUFFIX
=
information accumulated from right to left

The accumulated information could be:

sum
maximum
minimum
XOR
GCD
product
frequency
count
Boolean state
hash
DP state

Whenever you repeatedly ask:

"What happened before this index?"

think:

PREFIX

Whenever you repeatedly ask:

"What remains after this index?"

think:

SUFFIX

And whenever you need both:

LEFT INFORMATION
       +
CURRENT POSITION
       +
RIGHT INFORMATION

think:

PREFIX + SUFFIX

That simple mental model is one of the most useful tools in Data Structures and Algorithms.
