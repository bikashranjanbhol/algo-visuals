Prefix and suffix techniques

Array problems keep asking the same two questions: "what happened before this index?" and "what remains after it?" Instead of rescanning every time, sweep once in each direction and remember. That one habit turns O(n²) into O(n) and turns range queries into a subtraction.

Prefix = left to right

Information accumulated over A[0 … i]. "What have I seen so far?"

Suffix = right to left

Information accumulated over A[i … n−1]. "What is still ahead of me?"

Any operation works

Sum is the famous one, but max, min, XOR, GCD, product and counts all follow the same recurrence.

Both sides at once

prefix[i−1] and suffix[i+1] describe everything except index i. That pattern solves a whole family of problems.

Build one, step by step

Every prefix array comes from one recurrence: prefix[i] = combine(prefix[i−1], A[i]). Pick the operation and the direction, then watch it fill in. The code updates to match.

Time: one pass, O(n). Each cell costs one combine, which is why rescanning is never needed.

The range-query trick

Use an array of size n+1 with prefix[0] = 0. Then the sum of any range A[L … R] is prefix[R+1] − prefix[L]: the unwanted left part is subtracted away. Pick L and R and watch which two cells are used.

Why it matters at scale

n elements, q range queries. Rescanning costs about n per query; prefix sums cost n once, then 1 per query.

Everything except me

The most important prefix + suffix pattern: for each index, combine what's strictly to its left with what's strictly to its right. Product of Array Except Self is the classic. Watch the two passes build left and right, then multiply.

left[i] = product of A[0 … i−1] // strictly before i right[i] = product of A[i+1 … n−1] // strictly after i ans[i] = left[i] * right[i] // in code, left is built left-to-right, right is built right-to-left left[0] = 1; for (i = 1 … n−1) left[i] = left[i−1] * A[i−1]; right[n−1] = 1; for (i = n−2 … 0) right[i] = right[i+1] * A[i+1];

Including vs excluding the current element

A prefix that includes i is prefix[i]. "Strictly before i" is prefix[i−1], and "strictly after i" is suffix[i+1]. Most bugs in this pattern come from mixing those up, and from forgetting that i = 0 has nothing to its left and i = n−1 has nothing to its right. Use an identity value (0 for sum, 1 for product, −∞ for max) at the edges.

The same idea in famous problems

Pivot index: left sum equals right sum

Move i. Left is the sum strictly before i, right is the sum strictly after. You don't even need an array here: a running total is enough, because right = total − left − A[i].

Stock profit: prefix min meets suffix max

Buy low on an earlier day, sell high on a later day. Prefix min answers "cheapest so far", suffix max answers "best price still coming". The two sides store different things, which is allowed.

Trapping rain water: prefix max and suffix max

Water above a bar is held in by the tallest wall on each side: water[i] = min(leftMax[i], rightMax[i]) − height[i]. Move i to see the two walls that matter for that column.

i = 5

Difference array: range updates in O(1)

The inverse trick. To add x to every element in A[L … R], write +x at L and −x at R+1 in a difference array. One prefix sum at the end rebuilds the real values, no matter how many updates you made.

More places it hides

Valid split

Split so that everything on the left ≤ everything on the right. That's prefixMax[i] ≤ suffixMin[i+1], checked for every i in one pass.

Parentheses balance

Treat ( as +1 and ) as −1. The prefix sum is the running balance. Valid means it never dips below 0 and ends at exactly 0.

Prefix count

"How many 1s between L and R?" is a prefix sum of a condition: prefix[i+1] = prefix[i] + (A[i] == 1), then subtract. Same for letters in a string.

GCD except me

GCD of the array after removing index i is gcd(prefixGcd[i−1], suffixGcd[i+1]). Same shape as product-except-self.

2D prefix sums

Rectangle sums on a grid: P[i+1][j+1] = M[i][j] + P[i][j+1] + P[i+1][j] − P[i][j]. Add the two overlapping rectangles, subtract the corner counted twice.

Kadane, viewed as a prefix

bestEnding[i] = max(A[i], bestEnding[i−1] + A[i]) is a left-to-right recurrence too. "Prefix" is about direction, not about sums.

Which operations can answer any range?

Subtraction only works when the operation has an inverse. Without one, prefix arrays still answer "from the start up to i", but not arbitrary L … R.

Mistakes everyone makes once

Wrong loop direction for suffix

suffix[i] depends on suffix[i+1], so the loop must run from n−2 down to 0. Starting at 0 reads cells you haven't filled yet.

Off the end of the array

prefix[i−1] at i = 0 and suffix[i+1] at i = n−1 don't exist. Guard them with an identity value or use the n+1 layout with a leading 0.

Integer overflow

10⁵ values up to 10⁹ sum to about 10¹⁴, far past 32-bit. Use 64-bit integers for prefix sums; in Python this isn't an issue, in C++ and Java it is.

Mixing indexing styles

Style 1: prefix[i] = sum of A[0 … i], range = prefix[R] − prefix[L−1], with a special case at L = 0. Style 2: leading 0, range = prefix[R+1] − prefix[L], no special case. Pick style 2 and stick with it.

A short strategy

  1. Am I rescanning the same left or right portion over and over?
  2. What single piece of information do I need from that side: sum, max, min, count, XOR, GCD, a boolean?
  3. Is it about the left side (prefix), the right side (suffix), or both sides of every index (prefix + suffix)?
  4. Do I need all the values later (keep the array), or just the running value as I sweep (keep one variable)?
  5. Check the edges: what's the identity value when there's nothing to the left or right?

Templates

Check yourself

A = [2, 4, 1, 7, 3]. What's the sum of A[1 … 3] using the n+1 prefix array?

prefix = [0, 2, 6, 7, 14, 17]. Sum = prefix[4] − prefix[1] = 14 − 2 = 12, which is 4 + 1 + 7.

Why can't you get the max of A[2 … 4] from a prefix max array?

prefixMax[4] tells you the biggest value in A[0 … 4], but you can't "subtract" A[0 … 1] out of it: if the overall max sits at index 0, you have no idea what the max of A[2 … 4] is. Max has no inverse.

For "product except self", what should left[0] and right[n−1] be?

1, the identity for multiplication: there's nothing to the left of index 0 and nothing to the right of the last index, and multiplying by 1 changes nothing.

You add 5 to A[2 … 4] and 2 to A[0 … 1] using a difference array of length 6. What does diff look like?

diff = [2, 0, 3, 0, 0, −5]. Start +2 at 0, cancel with −2 at 2, start +5 at 2 (so index 2 nets +3), cancel with −5 at 5. Prefix-summing gives [2, 2, 5, 5, 5, 0].
